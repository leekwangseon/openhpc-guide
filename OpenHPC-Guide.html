클러스터 사용 안내

처음 접속하는 순간부터 계산 결과를 내려받을 때까지, 필요한 순서대로 안내합니다.

무엇을 하시겠어요?

처음 접속하기접속 정보 확인 · SSH 로그인 · 접속 대상 확인 파일 주고받기작업 폴더 · 입력 파일 업로드 · 결과 다운로드 계산 시작하기사용할 노드 확인 · 실행 · 진행 확인 · 종료 문제 해결하기접속 오류 · 권한 · 실행 환경 · 문의 방법

처음 사용한다면

  1. 담당자에게 받은 접속 주소, 포트, 개인 계정을 준비합니다.
  2. 접속 안내에 따라 로그인하고 접속한 서버를 확인합니다.
  3. 파일 안내에 따라 작업 폴더에 입력 파일을 올립니다.
  4. 사용할 계산 노드와 자원 범위를 확인한 뒤 계산 안내를 진행합니다.

사용 전에 알아두세요

  • 접속한 서버와 계산할 서버가 다를 수 있습니다. 로그인 서버에서 장시간 계산해도 되는지는 담당자 안내를 확인해 주세요.
  • 사용 방식은 장비마다 다릅니다. 계산 노드를 직접 사용하는 환경과 Slurm으로 작업을 제출하는 환경이 있습니다. 안내받은 방식에 해당하는 절차를 사용하세요.
  • 결과는 지정된 저장 공간에 보관하세요. 임시 폴더는 재부팅이나 정리 작업으로 삭제될 수 있습니다.

이 안내서는 여러 클러스터에서 공통으로 사용하는 방법을 설명합니다. 실제 주소·프로그램 경로·사용 정책은 장비 담당자가 전달한 안내를 확인해 주세요.

접속하기

담당자에게 받은 서버 주소·SSH 포트·개인 계정을 준비합니다. 아래 명령의 YOUR_LOGIN_HOST, YOUR_SSH_PORT, YOUR_USER를 각각 그 값으로 바꿔 입력하세요. 값을 받지 못했다면 먼저 담당자에게 문의해 주세요.

내 PC에서 실행

Windows는 PowerShell/OpenSSH 또는 조직에서 허용한 SSH 클라이언트를, macOS·Linux는 터미널을 사용할 수 있습니다. 클라이언트별 기능·라이선스는 해당 배포처에서 확인합니다.

ssh -p YOUR_SSH_PORT YOUR_USER@YOUR_LOGIN_HOST

처음 접속할 때 표시되는 호스트 키 지문은 관리자에게 받은 지문과 비교합니다. 호스트 키가 변경되었다는 경고가 나오면 재설치·교체 여부를 확인합니다. 경고를 우회하거나 기존 키를 무조건 삭제하지 않습니다.

비밀번호 입력 중 화면에 글자가 보이지 않는 것은 정상입니다. 비밀번호·다중 인증·키 인증 중 현장에서 지정한 방법을 사용합니다.

중계 서버·VPN이 필요한 현장에서는 관리자에게 받은 전용 접속 절차를 사용합니다. 중계 서버의 127.0.0.1과 내 PC의 127.0.0.1은 다른 대상입니다. 리버스 유지보수 통로를 일반 사용자 접속 경로로 임의 사용하지 않습니다.

접속한 서버에서 확인

hostname
whoami
pwd

현장 안내서의 로그인 노드 이름과 개인 계정이 표시되는지 확인합니다. 계산 노드 접속이 별도로 필요한 경우에만 승인된 방식으로 이동합니다.

파일 주고받기

다음 예제는 HOME이 작업에 허용된 공유 경로일 때만 사용합니다. 별도 프로젝트 경로가 있으면 그 경로에서 시작합니다.

mkdir -p "$HOME/work/first-test"
cd "$HOME/work/first-test"
pwd
df -h .

내 PC에서 작은 파일을 올리는 예제입니다. YOUR_USER_HOME은 /home/개인계정 등 관리자가 안내한 절대 경로로 바꿉니다.

scp -P YOUR_SSH_PORT ./input.dat YOUR_USER@YOUR_LOGIN_HOST:YOUR_USER_HOME/work/first-test/

결과를 내 PC의 현재 폴더로 내려받습니다.

scp -P YOUR_SSH_PORT YOUR_USER@YOUR_LOGIN_HOST:YOUR_USER_HOME/work/first-test/result.dat ./

SSH는 소문자 -p, SCP는 대문자 -P로 포트를 지정합니다. GUI 파일 전송에서는 SFTP를 선택하고 같은 주소·계정·SSH 포트를 사용합니다. 중계 접속이면 별도 SFTP 중계 설정이 필요할 수 있습니다.

대용량·다수 파일은 양쪽에 rsync가 제공될 때 사용할 수 있습니다. 재실행 시 이미 전송된 내용을 활용하며 --partial은 중단된 부분 파일을 보관합니다. 대상 경로와 덮어쓰기 여부를 먼저 확인합니다.

rsync -av --partial --progress -e 'ssh -p YOUR_SSH_PORT' ./inputs/ YOUR_USER@YOUR_LOGIN_HOST:YOUR_USER_HOME/work/first-test/inputs/

이 예제에는 파일 삭제 옵션을 넣지 않았습니다. 중요한 결과는 현장 백업·보관 정책에 따라 별도 보존합니다.

계산 실행과 결과 확인

담당자에게 안내받은 실행 방식을 사용하세요. 직접 실행하는 환경은 첫 번째 절을, Slurm을 사용하는 환경은 두 번째 절을 확인합니다.

직접 실행

이 절차는 스케줄러를 통하지 않는 실행이 허용되고 노드 직접 접속 권한이 제공된 경우에만 적용합니다. ANSYS 등 제품 자체의 원격 실행 도구를 사용하는 현장은 제품별 안내를 우선합니다.

실행 전

관리자 또는 예약 체계에서 사용할 노드·CPU·메모리·종료 시각을 확인합니다. 아래 명령은 상황을 보는 보조 수단이며 예약이나 자원 점유권을 보장하지 않습니다.

ssh YOUR_APPROVED_NODE
hostname
uptime
free -h
ps -u "$USER" -o pid,etime,%cpu,%mem,args

w는 로그인 세션을 보여줄 뿐, 모든 계산 작업을 보여주지는 않습니다. 다른 사람이 로그인하지 않았어도 계산 중일 수 있습니다. GPU 확인 명령은 해당 GPU와 도구가 설치된 노드에서만 사용합니다.

계산 시작

지정한 공유 작업 폴더에서 제품별 안내 명령으로 실행합니다. 다음은 문법 설명용이며 실제 실행 명령이 아닙니다.

YOUR_APPLICATION YOUR_CONFIRMED_OPTIONS > run.log 2>&1

코어 수·MPI 방식·노드 목록·메모리 옵션은 프로그램별로 다릅니다. 단일 노드 계산 성공 후 멀티노드 계산을 시험합니다. 여러 노드에서 같은 파일을 동시에 덮어쓰지 않도록 작업 폴더와 출력 파일을 분리합니다.

ANSYS의 경우 제품·버전·실행 경로·라이선스 서버·HPC 사용 권한·MPI/IB 설정을 설치 담당자에게 확인합니다. 클러스터의 일반 OpenMPI 모듈을 ANSYS용 MPI로 자동 지정하지 않습니다.

접속 종료 후에도 유지해야 하는 작업

현장에서 tmux 사용을 허용하고 설치한 경우의 예입니다. 프로그램을 실행할 계산 노드에서 시작합니다.

tmux new -s first-test

세션 안에서 계산을 시작합니다. Ctrl+b를 누른 뒤 d를 누르면 세션에서 분리됩니다. 같은 노드·같은 계정으로 돌아와 다시 연결합니다.

tmux attach -t first-test

tmux는 노드 재부팅·장애를 견디는 작업 관리자가 아니며, 현장의 로그아웃 정리 정책에 따라 유지되지 않을 수 있습니다. 긴 계산에는 프로그램의 체크포인트 기능과 승인된 실행 방식을 확인합니다.

진행 확인과 중지

다른 접속 세션에서도 작업이 실행되는 같은 노드·같은 경로에서 확인합니다.

tail -n 50 run.log
tail -f run.log

tail -f는 Ctrl+c로 종료해도 계산이 중단되지 않습니다. 계산 자체는 제품의 정상 종료·체크포인트 저장 기능을 먼저 사용합니다. 프로세스를 종료해야 하면 본인 PID와 작업을 확인한 뒤 kill -TERM PID를 사용합니다. MPI 작업은 여러 프로세스를 만들 수 있으므로 실행기 또는 제품이 안내한 종료 방법을 따릅니다. killall, 다른 사용자의 PID, 강제 종료를 일반 절차로 사용하지 않습니다.

Slurm으로 작업 제출

Slurm을 사용하지 않는 현장은 이 절을 건너뜁니다. 파티션·제한 정책은 현장 안내서에 따릅니다.

sinfo
squeue -u "$USER"

첫 배치 작업은 계산하지 않는 작은 시험으로 시작합니다. 로그인 노드의 공유 작업 폴더에서 다음 파일을 만듭니다.

cat > hello.slurm <<'EOF'
#!/bin/bash
#SBATCH --job-name=hello
#SBATCH --nodes=1
#SBATCH --ntasks=1
#SBATCH --cpus-per-task=1
#SBATCH --time=00:02:00
#SBATCH --output=hello-%j.out
hostname
date
EOF
sbatch -p YOUR_PARTITION hello.slurm

제출 응답의 Job ID를 기록하고 squeue -u "$USER"로 확인합니다. 완료 후 현재 폴더의 hello-작업번호.out을 확인합니다. 취소는 scancel YOUR_JOB_ID를 사용합니다.

srun hostname 같은 명령은 실행할 명령이 끝나면 종료됩니다. srun --pty bash로 대화형 셸을 시작한 경우 셸을 exit로 끝내야 합니다. 작업 목록에서 사라졌다는 것만으로 계산 성공을 판단하지 말고 출력·오류 로그와 결과를 확인합니다. sacct는 회계 기능이 구성된 경우에 사용합니다.

실행 환경 준비

Module이 제공되는 현장에서만 사용합니다.

module list
module avail
module show YOUR_MODULE
module load YOUR_MODULE

YOUR_MODULE은 실제 목록에 있는 프로그램/버전으로 바꿉니다. 작업 기록에 프로그램 버전과 모듈 목록을 남깁니다. module purge는 현재 환경을 모두 내리므로 실행 중인 작업의 환경 설정을 임의로 바꾸지 않습니다.

Conda·Python·컨테이너는 제공되는 경우에만 사용합니다. 오래된 예제의 Python·CUDA·딥러닝 버전을 그대로 설치하지 말고 프로젝트 요구 버전과 지원 조합을 확인합니다. 시스템 Python을 덮어쓰거나 일반 사용자 작업에 sudo pip를 사용하지 않습니다.

서버와 저장 공간 이해하기

어느 서버에서 무엇을 하나요?

구분 주로 하는 작업
로그인 서버 접속, 파일 준비, 계산 실행 준비, 결과 확인
계산 노드 실제 계산 실행
공유 저장 공간 여러 노드에서 사용할 입력·결과 파일 보관

한 장비가 로그인 서버와 관리 서버의 역할을 함께 수행할 수도 있습니다. 계산할 노드와 사용할 자원 범위는 담당자 또는 현장 예약 체계에서 확인합니다.

클러스터에 서버가 여러 대 있다고 해서 프로그램이 자동으로 여러 서버를 사용하는 것은 아닙니다. 멀티노드 계산은 프로그램의 지원 여부와 실행 설정을 확인해야 합니다.

파일을 어디에 두면 되나요?

경로 예시 용도 확인할 점
개인 HOME 개인 설정, 소스, 작은 작업 파일 공유 여부·용량 제한
프로젝트 또는 데이터 경로 입력 파일·계산 결과·공동 작업 본인에게 쓰기 권한이 있는 하위 폴더
공용 프로그램 경로 관리자가 설치한 프로그램 읽기·실행 용도
/tmp 또는 scratch 계산 중 사용하는 임시 파일 정리·재부팅 전에 결과 회수

폴더 이름만으로 공유·백업 여부를 판단하지 않습니다. 담당자가 지정한 경로를 사용하세요. 공유 저장 공간이나 RAID가 있다는 사실만으로 백업이 제공되는 것은 아닙니다.

함께 사용하는 장비입니다

  • 본인 계정을 사용하고 비밀번호·SSH 키를 공유하지 않습니다.
  • 배정받거나 예약한 CPU·메모리·GPU 범위에서 계산합니다.
  • 다른 사용자의 작업이나 파일을 임의로 종료·변경하지 않습니다.
  • 권한 오류가 나면 필요한 폴더 권한을 요청합니다. 공유 폴더 전체의 권한을 일괄 변경하지 않습니다.
  • 노드 재부팅·전원 조작·시스템 설정 변경은 담당자에게 요청합니다.

GUI와 선택 기능

GUI용 X11 전달은 내 PC의 X 서버·서버 설정이 모두 필요합니다. 일반 SSH 접속과 별도 기능입니다. ssh -X를 먼저 사용하고, 신뢰하는 서버에 한해 필요 시 -Y 사용 여부를 관리자에게 확인합니다. 계산 노드까지의 GUI 접속은 승인된 별도 절차를 따릅니다.

Jupyter는 X11을 필수로 요구하지 않습니다. 현장에서 허용한 실행 노드에 서버를 띄우고 SSH 로컬 포트 전달로 브라우저에서 접속할 수 있습니다. 다음은 내 PC에서 실행 노드에 직접 SSH 접속 가능한 경우의 예입니다.

실행 노드에서:

jupyter lab --no-browser --ip=127.0.0.1 --port=8888

내 PC의 별도 터미널에서:

ssh -N -L 127.0.0.1:8888:127.0.0.1:8888 -p YOUR_NODE_SSH_PORT YOUR_USER@YOUR_EXECUTION_HOST

내 PC 브라우저에서 http://127.0.0.1:8888을 열고 서버가 안내한 인증 절차를 따릅니다. 토큰은 공유하지 않습니다. 중계·Slurm 자원 배정이 필요한 현장에는 이 명령을 그대로 적용하지 말고 관리자의 터널·작업 할당 절차를 받습니다. 포트 충돌 시 양쪽 포트와 URL을 함께 조정합니다.

컨테이너는 관리자가 제공·허용한 실행기와 이미지로 사용합니다. Docker 그룹 권한은 일반적인 프로그램 실행 권한보다 강합니다. 그룹 가입을 자동 요청하거나 rootless 구성의 보안 보장을 임의로 가정하지 않습니다. Apptainer/Singularity도 호스트 경로 바인드·네트워크·GPU 접근 정책을 따릅니다.
