# 클러스터 개념과 명령어 읽기

## 클러스터를 사용하는 이유

여러 서버의 실행 환경을 통일하고 여러 사용자가 계산 자원을 나누어 사용하기 위한 환경입니다. 관리 도구는 OS·계정·설정을 배포하고, 스케줄러는 사용하는 현장에서 자원을 배정합니다. 공유 저장소는 입력·결과·프로그램을 여러 노드가 같은 경로로 접근하게 합니다.

로그인 노드는 접속·준비, 계산 노드는 계산, 관리 노드는 계정·부팅·서비스 운영을 담당합니다. 역할을 겸하는 장비도 있습니다. Ethernet과 InfiniBand 같은 통신망, NFS·병렬 파일시스템 같은 저장소, CPU·GPU·메모리의 구성은 현장마다 다릅니다.

## 기본 용어

| 용어 | 의미 |
|---|---|
| SSH / SCP / SFTP | 원격 접속 / SSH 기반 파일 복사 / 파일 전송 프로토콜 |
| X11 forwarding | 원격 GUI 화면을 내 PC의 X 서버로 전달 |
| HOME / 작업 경로 | 개인 설정 공간 / 계산에 사용하는 폴더 |
| PATH | 명령 실행파일을 검색하는 경로 목록 |
| 환경변수 | 프로그램의 동작·경로·장치 선택 등에 쓰이는 값 |
| Module / Conda 환경 | 공유 프로그램의 버전별 환경 / 프로젝트별 패키지 환경 |
| MPI | 여러 프로세스가 데이터를 주고받으며 계산하는 방식 |
| 컨테이너 | 호스트 커널을 공유하면서 실행 환경을 묶어 제공하는 방식 |
| Slurm / PBS | 작업 자원을 배정하는 스케줄러 제품. 동일 명령을 사용하지 않음 |
| Job / Step | 작업 / 작업 안에서 실행하는 단계 |
| Partition / Queue | 노드의 논리적 묶음 / 대기 작업 목록 |
| Account / Association | Slurm의 프로젝트 단위 / 사용자·계정·클러스터 등의 연결 |
| QoS | 작업 우선순위·사용 제한 등에 적용하는 정책 묶음 |
| GRES / TRES | GPU 등 일반 자원 / 사용량을 추적하는 자원 항목 |
| Fairshare / Backfill | 사용 이력에 따른 공정 배정 / 기존 예약을 지연시키지 않는 빈 시간 활용 |

하드웨어 코어 수와 논리 CPU 수는 다를 수 있습니다. 병렬 프로세스 수와 프로세스당 스레드 수를 구분하고, 메모리·라이선스 제한까지 고려해 실행합니다.

## Bash 명령 읽기

| 표기 | 뜻 |
|---|---|
| `~`, `$HOME` | 내 홈 디렉터리 |
| `$USER`, `${NAME}` | 환경변수·셸 변수의 값 |
| `#` | 주석. `#SBATCH`는 배치 파일에서 Slurm 지시문 |
| `>` / `>>` | 파일 덮어쓰기 / 파일 끝에 추가 |
| `2>&1` | 표준 오류를 표준 출력과 같은 대상으로 보냄 |
| `\|` | 앞 명령의 출력을 다음 명령의 입력으로 전달 |
| `&&` / `\|\|` | 앞 명령 성공 시 / 실패 시 다음 명령 실행 |
| `;` | 성공 여부와 무관하게 다음 명령 실행 |
| `\` | 줄 끝에서 다음 줄과 이어서 실행. 뒤에 공백을 넣지 않음 |
| `&` | 백그라운드 실행. 로그아웃·재부팅 후 생존 보장은 아님 |
| `'문자열'` / `"문자열"` | 변수 확장 없이 그대로 / 변수 값을 확장하여 사용 |

`cat > 파일 <<'EOF'`는 지정 문자열까지의 내용을 파일에 쓰며 내부의 `$변수`를 바로 확장하지 않습니다. `.bashrc`에 `>`를 사용하면 기존 설정이 사라질 수 있습니다. 수정 전 사본을 보관하고 필요한 줄만 편집합니다.

## 상황 확인 명령

```bash
hostname
whoami
id
pwd
ls -lh
df -h .
du -sh "$HOME"
free -h
uptime
w
```

`df`는 파일시스템 여유 공간, `du`는 디렉터리의 사용량입니다. 큰 공유 디렉터리의 재귀 탐색은 부하가 될 수 있습니다. quota는 파일시스템별 도구와 현장 정책을 확인합니다. `alias`로 만든 별칭은 다른 서버나 배치 스크립트에 없을 수 있으므로 표준 명령을 우선합니다.
