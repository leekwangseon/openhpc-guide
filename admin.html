관리자 운영 안내

계정·계산 노드·공유 저장소를 관리하는 담당자를 위한 문서입니다. 일반적인 접속과 계산 방법은 사용자 안내에서 확인할 수 있습니다.

일상 점검

대상 확인할 내용
서버 접속 가능 여부, 시간, CPU 부하, 메모리
저장소 용량·inode, 마운트, 사용자 쓰기 권한, quota
계산 노드 OS 부팅, 인증, 프로그램 접근, 하드웨어 오류
고속망 링크 상태·속도, 실제 병렬 통신
스케줄러 사용 시 서비스·노드 상태, 실제 시험 작업

기본 확인 명령입니다. 존재하는 기능과 현장 정책에 맞춰 사용합니다.

hostname
uptime
free -h
df -hT
findmnt -t nfs,nfs4
systemctl --failed

서비스가 실행 중이라는 표시만으로 전체 상태를 판단하지 않습니다. 개인 사용자 계정의 접속·파일 쓰기·작은 계산까지 확인합니다. BMC 전원 On과 OS 부팅 성공도 구분합니다.

사용자 계정

사용자 추가 전 UID/GID 충돌, 프로젝트 그룹, 사용 기간, 저장 공간·quota를 확인합니다. 실제 인증 체계에 맞춰 계정을 생성하고 계산 노드의 계정 매핑과 인증도 반영합니다.

추가 후에는 해당 사용자의 접속·공유 경로 쓰기·프로그램 실행을 시험합니다. 비밀번호나 개인 SSH 비밀키를 공용 설정 파일에 넣지 않습니다.

계정 사용 종료 시 모든 인증 경로와 실행 중 작업을 확인합니다. 계정 비활성화와 홈·프로젝트 데이터 삭제는 분리하여 처리하고 보존 정책·소유자 확인을 거칩니다.

프로그램·라이브러리 추가

공용 응용프로그램은 모든 대상 노드가 같은 경로로 사용할 수 있도록 구성합니다. OS 라이브러리는 필요한 로그인 서버와 계산 노드 이미지에 각각 반영합니다.

RAM 기반 계산 노드에서는 실행 중인 노드에만 설치한 변경이 재부팅 후 사라질 수 있습니다. 영구 이미지·overlay·구성 관리 대상도 함께 갱신해야 합니다.

  1. 적용할 프로그램·버전·노드와 점검 시간을 정합니다.
  2. 변경 대상과 승인된 범위의 이전 설정을 보관하고 복구 방법을 정합니다.
  3. 사용하는 배포 도구의 버전에 맞춰 영구 구성을 변경합니다.
  4. 시험 노드를 새 구성으로 부팅하고 인증·마운트·실행 환경을 확인합니다.
  5. 작은 단일 노드 계산 후 필요한 멀티노드·고속망·라이선스 시험을 진행합니다.
  6. 정상 확인 후 나머지 노드에 적용합니다.

Warewulf 3의 wwsh·wwvnfs와 Warewulf 4의 wwctl은 관리 방식이 다릅니다. 다른 버전의 명령을 그대로 혼용하지 않습니다. 커널·GPU·RDMA 변경은 제품이 지원하는 조합을 먼저 확인합니다.

공유 저장소

NFS 공유 대상은 필요한 호스트·관리망으로 제한하고 기본적으로 root_squash를 유지합니다. 공유 경로·사용자 그룹·읽기/쓰기·quota 정책을 함께 확인합니다.

공유 설정 변경 후 서버의 exports와 클라이언트의 실제 마운트를 확인하고, 일반 사용자로 파일 생성·읽기를 시험합니다. 마운트 변경도 영구 계산 노드 구성에 반영해야 합니다.

재부팅과 유지보수

사용자와 점검 시간을 조정하고 새 작업이 시작되지 않도록 한 뒤 실행 중 작업을 확인합니다. 직접 실행 환경에서는 w나 squeue만으로 작업이 없다고 판단하지 않습니다. 실제 프로세스·응용프로그램 상태와 예약 기록을 함께 확인합니다.

Slurm을 사용하는 노드는 현장 절차에 따라 새 작업을 차단하고 작업 종료를 기다립니다. 직접 실행과 병행한다면 직접 작업도 따로 확인해야 합니다. 정상 종료·재부팅을 우선하고, 복귀 후 사용자 작업이 가능한지 검증합니다.

전체 정지·기동은 저장소와 핵심 서비스의 의존 관계에 따라 수행합니다. 현장의 인수 자료에 기재된 순서와 복구 절차를 사용하세요.

장애 확인 순서

증상 우선 확인
노드가 부팅되지 않음 전원·POST·하드웨어 이벤트 → NIC → DHCP·PXE → 커널·이미지 → 마운트
SSH 접속 실패 접속 경로 → 서비스·방화벽 → 호스트 키 → 계정·인증
파일 쓰기 실패 저장소·마운트 → 용량·quota → UID/GID·그룹·권한
병렬 계산 실패 단일 노드 실행 → 라이선스·경로·인증 → MPI·고속망 → 멀티노드 실행

과거 하드웨어 이벤트와 현재 오류를 구분하여 기록합니다. 반복적인 전원 조작이나 설정 초기화보다 발생 시각·대상 노드·로그·재현 조건을 먼저 확보합니다.

운영 기록과 지원 요청

현장 구성표에 소프트웨어 버전, 이미지·노드 대응, 공유 경로, 인증 방식, 서비스·로그 위치, 변경 내역과 복구 절차를 유지합니다. 접속 인증 정보는 승인된 별도 방식으로 보관합니다.

지원 요청 시에는 영향 범위, 시작 시각, 변경 이력, 오류 메시지, 지금까지 확인한 내용을 함께 전달합니다. 사용자 데이터나 인증 정보를 로그에 포함해야 하는 경우 먼저 전달 범위를 확인합니다.
